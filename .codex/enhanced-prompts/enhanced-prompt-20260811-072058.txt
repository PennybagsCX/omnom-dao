# PHASES (decompose, execute in order, ReAct per finding)

## Phase 0 — Discovery & Tooling
  1. Confirm dev server boots (npm run dev) and prod build is green
     (npm run build, npm run typecheck, npm run lint).
  2. Enumerate every page + layout + shared component and its token usage.
  3. Build a screenshot capture plan at all breakpoints.

## Phase 1 — Token & Theme Conformance
  For every component verify it uses semantic tokens, not raw hex:
    - Brand: gold #FFD700, gold-hover #E6C200, purple #8B5CF6
    - Surfaces: bg-deep #000, bg-surface #0a0a0a, bg-elevated #141414, border #262626
    - Text: primary #fafafa, muted #a1a1aa, dim #8b8b96
    - Status: success #10b981, danger #ef4444, warning #f59e0b
  Flag any hardcoded hex, any non-token rgba(), and any token drift from
  globals.css.

## Phase 2 — Responsive Audit (mobile-first, all breakpoints)
  Test every route at: 320px (small phone), 375px, 390px, 768px (md),
  1024px (lg), 1280px (xl), and 1440px+.
  Hard requirements:
    - ZERO horizontal overflow at any width >= 320px (check html/body
      overflow-x, fixed-width children, negative margins, long unbroken
      strings/addresses, table widths, code blocks).
    - Bottom nav visible only < md (md:hidden); desktop nav only >= md.
    - Grids: grid-cols-1 -> sm:grid-cols-3 progression correct.
    - Touch targets >= 44x44px on mobile.
    - No text < 14px on mobile; hero scales text-4xl -> sm:text-6xl.
    - Padding progression px-4 sm:px-6 lg:px-8 honored.

## Phase 3 — Accessibility (WCAG 2.1 AA, hard gate)
  - Color contrast: text-primary >=4.5:1, text-muted >=4.5:1, text-dim
    >=4.5:1 against EACH surface layer (deep/surface/elevated). Gold
    #FFD700 on bg-deep for primary text must pass (flag if used as body
    text). Verify gold-on-gold and purple-on-deep usages.
  - Focus-visible: 2px solid #FFD700 outline, 2px offset, present on EVERY
    interactive element (links, buttons, inputs, tabs, dialogs, selects,
    dropdowns, wallet connect).
  - Keyboard: full tab order, visible focus, no keyboard traps, Escape
    closes dialogs/dropdowns, Enter/Space activate.
  - Screen readers: aria-label on every icon-only button, aria-hidden on
    decorative icons, DialogTitle present (visually-hidden ok), landmarks
    (<main id="main-content">, header/nav/footer), skip-link present and
    functional.
  - Form labels: every input has an associated <label>.
  - prefers-reduced-motion: all framer-motion + CSS animations disabled.

## Phase 4 — Component Quality & Consistency
  - shadcn/ui new-york primitives unchanged in spirit; variants
    (button sizes/badges/tabs) used consistently.
  - Spacing scale honored (no arbitrary pixel gaps outside the system).
  - Border radius tokens (radius-lg/md/sm) used, no rogue rounded-* .
  - Loading states: skeleton-shimmer for async content on every async
    route; no layout shift; loading.tsx wired.
  - Empty states: every list view has a branded empty-state.
  - Error states: error.tsx + not-found.tsx are on-brand and recoverable.

## Phase 5 — Motion & Interaction Polish
  - Easing EASE = [0.22,1,0.36,1] used everywhere (no default linear).
  - Entrance: opacity 0->1, y 12->0, duration ~0.5s.
  - Scroll reveal: whileInView once:true, duration ~0.45s.
  - Stagger: delay = i * 0.1.
  - Phase transitions via AnimatePresence mode="wait".
  - No janky transforms; will-change/transform used for animated layers.
  - Hover states present on all interactive desktop elements, suppressed
    or replaced on touch.

## Phase 6 — Brand & Identity Integrity
  - Logo: Dog icon h-7 w-7, wordmark "$OMNOM DAO" gradient
    from-gold to-purple, present in header (lg) and footer (sm).
  - Token always "$OMNOM" with $ prefix in display copy.
  - Holder classes (🐋🐬🐟) styled per BRAND_STANDARDS.md sec 10.
  - OG image / twitter image / favicon / manifest on-brand.

## Phase 7 — Performance & Build Hygiene
  - npm run build clean (no type errors, no lint errors).
  - Images optimized (next/image, sharp), no unoptimized <img> for
    raster assets.
  - No client-only work in server components; no accidental "use client"
    bloat.
  - Bundle: check for obviously heavy client deps shipped to landing.

## Phase 8 — World-Class Bar (subjective polish gate)
  - Visual hierarchy: one clear primary action per view.
  - Whitespace consistency; alignment grid respected.
  - Copy: brand voice (approachable but credible), no lorem, no typos.
  - Micro-interactions feel intentional, not gratuitous.
  - Dark theme depth: ambient glows (gold/10, purple/20 blur-[120px])
    used where the spec calls for them, not overused.

# OUTPUT FORMAT (structured)
Deliver, in this order:
  1. EXECUTIVE SUMMARY — overall grade (A-F), top 5 strengths, top 5
     critical issues, headline risk.
  2. METHOD — tooling, breakpoints tested, routes covered, dates.
  3. FINDINGS TABLE (severity-ranked), columns:
     | ID | Severity (P0 blocker / P1 major / P2 minor / P3 polish) |
       Route | File:Line | Spec Violation | Evidence | Remediation |
  4. PER-ROUTE MATRIX — one row per route, columns:
     Responsive | A11y | Tokens | Motion | Empty/Loading | Grade.
  5. REMEDIATION PLAN — phased (P0 this week, P1 next sprint, P2/P3
     backlog), each item with effort estimate (S/M/L) and which spec
     rule it satisfies.
  6. EVIDENCE — screenshots at each breakpoint (paths), contrast
     measurements with ratios, reduced-motion proof.

# CONSTRAINTS
  - Anti-fabrication: never invent a token, ratio, or finding. If a
    check cannot be run, mark it [NOT RUN] with the reason.
  - Every finding must be reproducible: cite file:line + the spec rule.
  - Do not redesign the system; measure conformance and propose minimal,
    spec-aligned fixes.
  - Privilege/confidentiality: do not expose secrets; this is UI only.
  - Prefer running the dev server + Playwright for live evidence over
    static-only review; fall back to static when a route needs auth.

# SUCCESS CRITERIA (definition of done)
  - All 11 routes audited at >=5 breakpoints each.
  - Contrast measured for every text token on every surface.
  - Zero P0 findings remaining OR each P0 has a documented remediation
    owner + effort.
  - Findings table is exhaustive and severity-ranked.
  - Every recommendation ties back to a DESIGN_SYSTEM.md / BRAND_STANDARDS
    .md section.
